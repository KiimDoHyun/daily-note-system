# Daily Note 자동화 - 설계

일일노트를 매일 자동 생성하고, 이월·완료·드롭·보관 흐름을 스크립트가 대신 처리하여 사용자는 오직 그날의 할일만 적으면 되도록 하는 시스템 설계.

---

## Part 1. 업무 관리 체계

### 1.1 기본 개념

이 시스템이 다루는 최소 단위는 **할일(Task)** 이다. 할일은 데일리 노트 안의 체크박스 한 줄로 표현된다.

```
- [ ] SNMP 쿼리 결과 필터 개선
```

할일은 시간이 흐르면서 6가지 상태 중 하나를 가진다. 상태 전이는 대부분 스크립트가 매일 아침(일일노트 생성 시점) 자동으로 판정한다.

### 1.2 상태 종류

| 상태 | 표기 | 정의 | 저장 위치 |
|---|---|---|---|
| **활성** | `- [ ] 할일` | 오늘의 할일 섹션에 새로 추가된 항목 | 당일 데일리 노트의 `할일` 섹션 |
| **이월** | `- [ ] 할일 (N일째 이월, MM-DD~)` | 어제 완료 못하고 넘어온 항목 (1~2일차) | 당일 데일리 노트의 `이월된 할일` 섹션 |
| **보류** | `🟠 - [ ] 할일 (3일째 이월, MM-DD~) (드롭 예정입니다)` (3일)<br>`🔴 - [ ] 할일 (4일째 이월, MM-DD~) (드롭 예정입니다)` (4일) | 3~4일째 이월된 경고 상태 | 당일 데일리 노트의 `이월된 할일` 섹션 |
| **완료** | `- [x] 할일` | 사용자가 체크박스에 표시한 항목 | 어제 데일리 노트 (원본 위치 그대로), 스크립트가 감지 후 월간 종합에 로그 |
| **드롭** | (텍스트만 이동) | 5일 초과 시 자동 이동, 또는 사용자가 `[-]` 표시 | 월간 드롭 문서 (`YYYY-MM 드롭.md`) |
| **보관** | `- [ ] 할일 #보관` (당일)<br>(다음 날부터는 데일리에서 사라짐) | 사용자가 명시적으로 보관 표시한 항목. 다음 날 스크립트가 감지 후 데일리에서 제거하고 보관함으로 이동 | `Notes/보관함.md` (상시 단일 문서) |

**장기 마커(`#장기`)** 는 상태가 아니라 **드롭 규칙 면제 태그** 다. `#장기` 가 붙은 할일은 5일 초과해도 드롭되지 않고 계속 이월된다. 상태는 여전히 활성/이월/보류 중 하나.

### 1.3 상태 전이 규칙

```
                  [활성]
                    │
                    ├─ 사용자 체크 ──────────────► [완료]
                    │
                    ├─ 사용자 #보관 마커 ──────► [보관]
                    │
                    ├─ 사용자 [-] 마커 ─────────► [드롭]
                    │
                    └─ 완료 안 함, 다음날 도래
                         │
                         ▼
                     [이월 1일차]
                         │
                         ├─ 체크 ──────────────► [완료]
                         │
                         └─ 미완료, 다음날
                              │
                              ▼
                     [이월 2일차]
                         │  ...
                         │
                         ▼
                     [보류 3일차 🟠]
                         │
                         ▼
                     [보류 4일차 🔴]
                         │
                         ├─ 체크 ──────────────► [완료]
                         │
                         ├─ #장기 마커 있음 ──► [이월 5일차] (드롭 면제)
                         │
                         └─ 그 외 ─────────────► [드롭]
```

**전이 판정 시점**: 모든 자동 전이는 **다음 날 일일노트가 생성되는 순간** 스크립트가 어제 노트를 읽어 결정한다. 실시간 감지 아님.

**영업일 기준**: 이월 일수 카운터는 주말을 건너뛴다. 금요일 미완료 항목은 월요일 노트에서 "1일째 이월" 로 표기된다.

### 1.4 각 상태의 수명

| 상태 | 언제까지 유지되나 |
|---|---|
| 활성 | 하루 (당일 24시) |
| 이월 (1~2일) | 최대 2 영업일 |
| 보류 (3~4일) | 최대 2 영업일 |
| 완료 | 영구 (원본 데일리 노트에 남고, 월간 종합에도 로그) |
| 드롭 | 월간 문서에 영구 기록. 사용자가 수동으로 부활 가능 |
| 보관 | 보관함 문서에 영구 기록. 데일리 노트에는 등장 안 함. 사용자가 수동으로 부활 가능 |

### 1.5 완료 감지 규칙

스크립트가 완료를 인식하는 방식은 **어제 노트에서 체크된(`- [x]`) 항목을 스캔** 하는 것이다. 두 섹션 모두 대상이다.

- `할일` 섹션에서 체크 → 당일 완료 (소요일 = 0일)
- `이월된 할일` 섹션에서 체크 → 태그의 시작일(`MM-DD~`) 부터 완료일까지 영업일 계산

완료 감지 결과는 월간 종합 문서에 append 된다. 완료된 항목은 다음 날 이월 대상에서 제외한다.

### 1.6 부활 규칙

드롭된 할일을 다시 하고 싶으면 사용자가 드롭 문서(`YYYY-MM 드롭.md`) 에서 해당 줄을 복사해서 오늘 데일리 노트의 `할일` 섹션에 붙여넣는다. 이때 이월 태그(`(5일째 이월, ...)`) 는 지우고 순수 할일 텍스트만 붙여넣기를 권장한다. 이렇게 하면 스크립트는 신규 활성 할일로 간주해서 이월 카운터가 다시 0부터 시작한다.

부활을 스크립트가 자동 감지하지는 않는다. 명시적 결정만이 유효하다.

### 1.7 마커 요약

| 마커 | 위치 | 의미 |
|---|---|---|
| `#장기` | 할일 텍스트 어디든 | 5일 드롭 규칙 면제, 무한 이월 |
| `#보관` | 할일 텍스트 어디든 | 다음 날 노트 생성 시 보관함으로 이동 |
| `[-]` | 체크박스 자리 | 다음 날 노트 생성 시 즉시 드롭 문서로 이동 |

마커 안내는 모든 데일리 노트 하단에 자동 삽입된다. 사용자가 매번 기억할 필요 없음.

## Part 2. 폴더 구조와 파일 포맷

### 2.1 전체 폴더 구조

```
Obsidian Vault/
└── Notes/
    ├── 보관함.md                          ← 상시 단일 문서
    ├── 2026-09/
    │   ├── 2026-09 종합.md                ← 월 첫 일일노트 생성 시 자동
    │   ├── 2026-09 드롭.md                ← 첫 드롭 발생 시 자동 (lazy)
    │   ├── 1주차/
    │   │   ├── 📅 2026-09-01.md
    │   │   ├── ...
    │   │   └── 📅 2026-09-05.md
    │   └── 2주차/
    │       ├── 📅 2026-09-08.md
    │       └── ...
    └── 2026-10/
        └── ...
```

월간 문서 두 개(`종합`, `드롭`) 는 주차 폴더와 같은 레벨. 이유는 검색·wikilink 접근성. 주차 폴더 안에 넣으면 여러 주차 어디에 둘지 애매하고 링크 경로도 지저분해짐.

### 2.2 파일 생성 시점

| 파일 | 시점 | 방식 |
|---|---|---|
| 데일리 노트 (`📅 yyyy-mm-dd.md`) | 매일 로그인 시 | Eager. 항상 자동 생성 |
| 월간 종합 (`YYYY-MM 종합.md`) | 그 달의 첫 일일노트 생성 시 | Eager. 빈 골격 만들고 대기 |
| 월간 드롭 (`YYYY-MM 드롭.md`) | 그 달에 첫 드롭 발생 시 | Lazy. 발생 전엔 존재 안 함 |
| 보관함 (`보관함.md`) | 첫 `#보관` 사용 시 | Lazy. 발생 전엔 존재 안 함 |

Lazy 방식을 쓰는 이유: 드롭·보관은 발생 안 하는 달·사용자도 있음. 빈 파일이 볼트에 쌓이면 지저분.

### 2.3 파일 포맷: 데일리 노트

```markdown
---
date: 2026-09-15
tags: [daily]
---

# 2026-09-15 데일리

## 📌 할일
- [ ] 
- [ ] 
- [ ] 

## ✅ 이월된 할일
- [ ] SNMP 쿼리 개선 (1일째 이월, 09-14~)
    - 원인은 OID 매칭에서 host 필터 누락
- [ ] 대시보드 위젯화 (2일째 이월, 09-11~)
🟠 - [ ] 헬스체크 맵 성능 (3일째 이월, 09-10~) (드롭 예정입니다)
🔴 - [ ] 릴리즈노트 필터 수정 (4일째 이월, 09-09~) (드롭 예정입니다)

## 💬 메모


---
📎 마커: `#장기`(드롭 면제) · `#보관`(보관함 이동) · `[-]`(즉시 드롭)
📂 [[2026-09 종합]] · [[2026-09 드롭]] · [[보관함]]
```

**포인트:**
- 섹션 이름 변경: `오늘의 목표` → `할일`, `미완료 이월` → `이월된 할일`. 아이콘은 기존 유지 (`📌`, `✅`, `💬`).
- 이월 항목 아래의 들여쓰기 하위 라인은 함께 이월됨(Part 1.1 의 종속 메모 방식).
- 상태별 표기(3일 🟠, 4일 🔴 + 드롭 예정 문구) 는 라인 앞·뒤에 붙는다.
- 하단 안내 블록(마커 설명 + 관련 문서 wikilink) 은 스크립트가 매일 자동 삽입.
- 메모 섹션은 매일 새로 시작. 이월 대상 아님.

### 2.4 파일 포맷: 월간 종합

```markdown
---
tags: [monthly-summary, 2026-09]
---

# 2026-09 월간 종합

> 이 문서는 스크립트가 매일 자동 갱신합니다.

## 📈 이번 달 요약
- 완료: 12건
- 드롭: 3건
- 보관 이동: 1건
- 평균 완료 소요: 1.4 영업일

## 1주차 (09-01 ~ 09-05)

### ✅ 완료
- 09-03 SNMP 쿼리 결과 필터 개선 (2영업일 소요, 09-01 시작)
- 09-04 대시보드 헤더 리팩터링 (당일)
- 09-05 릴리즈노트 링크 수정 (당일)

### ⏭️ 드롭
_없음_

### 📦 보관 이동
_없음_

## 2주차 (09-08 ~ 09-12)

### ✅ 완료
- 09-10 헬스체크 카드 css 정리 (당일)

### ⏭️ 드롭
- 09-11 헬스체크 맵 성능 개선 (09-04 시작, 5영업일 이월 후 드롭)

### 📦 보관 이동
- 09-12 SNMP 트랩 처리 개편
```

**포인트:**
- 상단 요약은 매일 재계산해서 덮어씀.
- 주차별 섹션은 append-only. 각 이벤트를 발생 날짜 순으로 추가.
- 이벤트 3종: 완료 / 드롭 / 보관 이동. **신규 추가 이벤트는 넣지 않음** (지나치게 시끄러워짐, 완료·드롭 시점에 시작일이 이미 표기됨).
- 소요일: 활성 → 완료면 "당일", 이월된 상태에서 완료면 "N영업일 소요, MM-DD 시작".
- 주차 계산은 데일리 노트 폴더 규칙과 동일 (1일 포함 주가 1주차, 월요일 기준).
- 월말 시점의 "진행 중" 섹션은 넣지 않음. 데일리 노트 자체가 그 역할.

### 2.5 파일 포맷: 월간 드롭

```markdown
---
tags: [monthly-drop, 2026-09]
---

# 2026-09 드롭된 업무

> 5일 초과 이월 또는 즉시 드롭(`[-]`) 처리된 항목.
> 살리려면 항목 텍스트만 복사해서 오늘 데일리의 `할일` 섹션에 붙여넣기 (이월 태그 제거).

- [-] 헬스체크 맵 성능 개선 (09-04 시작, 09-11 드롭, 5영업일 이월)
- [-] 대시보드 헤더 리팩터링 (09-08 시작, 09-16 드롭, 6영업일 이월)
- [-] 이벤트 배열 조건 실험 (09-12 즉시 드롭)
```

**포인트:**
- 체크박스는 `- [-]` 로 표기. 옵시디언에서 취소선 렌더링되어 "드롭됨" 이 시각적으로 명확.
- append-only. 새 드롭이 발생하면 맨 아래에 한 줄 추가.
- 부활은 사용자가 텍스트만 복사해서 데일리로 옮기는 방식. 스크립트가 부활을 자동 감지하지 않음.
- 드롭 문서를 살펴보다가 정말 필요없다 싶으면 사용자가 라인을 지워도 됨(수동 정리 허용).

### 2.6 파일 포맷: 보관함

```markdown
---
tags: [archive]
---

# 보관함

> 지금은 아니지만 나중에 참고할 할일들.
> 살리려면 항목 텍스트만 복사해서 오늘 데일리의 `할일` 섹션에 붙여넣기.

## 2026-09
- [ ] SNMP 트랩 처리 개편 (보관: 09-12)
- [ ] 다크모드 대시보드 (보관: 09-18)

## 2026-10
- [ ] ...
```

**포인트:**
- 상시 단일 문서. 월 경계와 무관.
- 월별 그룹(`## YYYY-MM`) 으로 정리. 스크립트가 첫 항목 추가 시 그룹 헤더 만들고, 이후엔 해당 그룹에 append.
- 체크박스는 `- [ ]`. 부활 가능성이 있으니 활성 상태로 유지.
- 사용자가 파일에서 직접 라인을 지우면 완전 삭제로 간주.

### 2.7 파일 생성·갱신 흐름 요약

일일노트 생성 시점에 스크립트가 하는 일:

1. 오늘 데일리 노트 생성
2. 어제 데일리 노트 스캔
   - `[x]` 체크된 항목 → 월간 종합의 "완료" 에 append
   - `#보관` 태그 붙은 항목 → 보관함으로 이동
   - `[-]` 표시 항목 → 월간 드롭으로 이동
   - 나머지 미완료 항목 → 오늘 데일리의 `이월된 할일` 로 옮기고 카운터 +1
   - 카운터 5일 도달 + `#장기` 없음 → 월간 드롭으로 이동
3. 필요 시 월간 종합·드롭·보관함 문서 신규 생성
4. 월간 종합의 상단 요약(카운트, 평균 소요일) 재계산 후 덮어씀

## Part 3. 스크립트 처리 흐름

### 3.1 실행 트리거

- launchd (`~/Library/LaunchAgents/com.doh.obsidian-daily-note.plist`) 가 로그인 시 스크립트 실행
- 수동 실행도 가능: `bash ~/.claude/scripts/create-daily-note.sh`
- 오늘 데일리 노트가 이미 있으면 즉시 스킵 (idempotent)

### 3.2 전체 처리 순서

```
[Start]
  │
  ├─ 오늘 노트 이미 존재? ─── Yes ──► [Exit]
  │
  ├─ 어제 노트 찾기 (영업일 역탐색)
  │     └─ 없으면 → 빈 이벤트로 진행
  │
  ├─ 어제 노트 파싱 → 이벤트 목록 생성
  │     ├─ 완료 이벤트
  │     ├─ 드롭 이벤트 ([-] 표시)
  │     ├─ 보관 이벤트 (#보관 태그)
  │     └─ 이월 대상 (나머지 미완료)
  │
  ├─ 이월 카운터 계산
  │     └─ 5일 도달 + #장기 없음 → 드롭 이벤트로 재분류
  │
  ├─ 필요 시 월간 문서 신규 생성
  │     ├─ 이 달의 첫 노트면 → 월간 종합 생성
  │     ├─ 첫 드롭 이벤트면 → 월간 드롭 생성
  │     └─ 첫 보관 이벤트면 → 보관함 생성
  │
  ├─ 이벤트 append
  │     ├─ 완료 → 어제 날짜가 속한 월의 종합 문서
  │     ├─ 드롭 → 어제 날짜가 속한 월의 드롭 문서
  │     └─ 보관 → 보관함 (어제 날짜 기준 월 그룹)
  │
  ├─ 오늘 데일리 노트 생성 (이월 항목 포함, 하단 안내 삽입)
  │
  └─ 이번 달 종합 문서 상단 요약 재계산 → 덮어쓰기
```

### 3.3 어제 노트 찾기 (영업일 기반)

```
오늘 요일   →  어제(직전 영업일)   →  이월 카운터 증가폭
─────────────────────────────────────────────────
월          →  지난 금요일         →  +1 (주말 스킵)
화~금       →  하루 전             →  +1
```

토·일에는 launchd 가 실행돼도 노트를 만들지 않는다. 주말 노트가 생기면 이월 카운터 계산이 꼬이고, 실제로 볼 일도 없다.

**최대 역탐색 범위**: 14 캘린더일. 그 이상 부재였다면 이월 개념이 무의미해지므로 어제 노트 없음으로 간주.

### 3.4 라인 파싱 규칙과 블록 개념

#### 블록 정의

파싱과 상태 전이의 최소 단위는 **할일 블록**. 한 블록 = 최상위 체크박스 라인 + 그 아래 모든 들여쓰기 하위 라인 (다음 최상위 라인 직전까지).

```
- [ ] SNMP 쿼리 개선                    ← 블록 시작 (인덴트 0)
    - 원인은 host 필터 누락              ← 블록 소속 (인덴트 있음)
    - [ ] 서브: OID 매칭 로직 수정       ← 블록 소속 (서브 할일)
        - 관련 파일: rest/snmp.ts        ← 블록 소속 (더 깊은 서브)
    - [x] 서브: 테스트 케이스 추가       ← 블록 소속 (완료된 서브)
- [ ] 대시보드 위젯화                    ← 새 블록 시작
```

블록 경계 판정: **인덴트가 0인 라인부터 다음 인덴트 0인 라인 직전까지**. 인덴트는 탭 또는 공백 2칸·4칸 모두 허용. 빈 라인은 블록 경계 아님(블록 안의 빈 라인은 블록 소속).

#### 최상위 라인 매치 패턴

| 유형 | 패턴 (개념) | 예시 |
|---|---|---|
| 활성 할일 (미완료) | `^- \[ \] (텍스트)` in `할일` 섹션 | `- [ ] SNMP 개선` |
| 활성 할일 (완료) | `^- \[x\] (텍스트)` in `할일` 섹션 | `- [x] SNMP 개선` |
| 이월 할일 (미완료) | `^(🟠 \|🔴 )?- \[ \] (텍스트) \((N)일째 이월, (MM-DD)~\)` | `- [ ] SNMP 개선 (2일째 이월, 09-14~)` |
| 이월 할일 (완료) | `^(🟠 \|🔴 )?- \[x\] (텍스트) \((N)일째 이월, (MM-DD)~\)` | `- [x] SNMP 개선 (2일째 이월, 09-14~)` |
| 즉시 드롭 | `^- \[-\] (텍스트)` | `- [-] 이 아이디어 폐기` |

#### 마커 감지 (최상위 라인 텍스트 내부)

- `#보관` 포함 여부 → 보관 이동
- `#장기` 포함 여부 → 드롭 규칙 면제

#### 블록 이동 보장

상태 전이(이월·완료·드롭·보관)는 항상 **블록 통째** 로 수행:

- **이월**: 어제 노트의 미완료 블록 전체를 오늘 `이월된 할일` 섹션에 통째로 옮김. 최상위 라인에만 이월 태그 추가·갱신, 하위 라인은 원본 그대로 유지.
- **완료**: 최상위 `[x]` 인 블록 발견 시 월간 종합에 append. 서브 체크박스 상태는 판정에 영향 없음.
- **드롭**: 5일 도달 또는 `[-]` 마커 시 블록 통째를 월간 드롭 문서로 이동.
- **보관**: `#보관` 마커 감지 시 블록 통째를 보관함으로 이동.

#### 인-데이 수정 처리

사용자가 오늘 `이월된 할일` 섹션의 특정 블록 아래에 새 메모나 서브를 추가한 경우, 그 라인들은 인덴트 규칙에 의해 자동으로 해당 블록 소속. 다음 날 스크립트는 같은 파싱 규칙으로 블록을 읽으므로 추가된 내용도 함께 이월됨.

#### 서브 체크박스 규칙

- 서브 `[x]` 상태는 이월 시 유지. 리셋하지 않음.
- 서브 완료는 개별 이벤트로 로그하지 않음. 월간 종합의 로그 단위는 최상위 할일뿐.
- 최상위가 `[ ]` 이면 서브가 모두 `[x]` 여도 계속 이월.
- 최상위가 `[x]` 이면 서브 상태 무관하게 완료 이벤트.

#### 인덴트 실수 방지

사용자가 하위 항목을 인덴트 없이 새 줄로 쓰면 별도 최상위 블록으로 오인됨. 이를 줄이기 위해 데일리 노트 하단 안내에 다음 문구 추가:

```
📎 하위 항목·메모는 반드시 들여쓰기(탭 또는 공백) 후 작성.
```

### 3.5 이벤트 우선순위

한 라인이 여러 조건에 걸릴 때 다음 순서로 판정 (위가 우선):

1. `[-]` → **즉시 드롭**
2. `[x]` → **완료**
3. `#보관` 포함 → **보관 이동**
4. `#장기` 포함 → **이월 (드롭 면제)**
5. 그 외 미완료 → **이월** (카운터 +1, 5일 도달 시 드롭)

예: `- [x] 할일 #보관` → 완료로 처리 (체크가 보관보다 우선).

### 3.6 파일 쓰기 순서

파일 시스템 부작용은 아래 순서로. 중간 실패 시 다음 실행에서 재시도되지만, 이 순서면 이중 기록 위험이 최소.

1. 어제 날짜가 속한 월의 종합 문서 신규 생성 (없으면)
2. 완료 이벤트 append → 종합 문서
3. 드롭 이벤트 처리
   - 그 달 드롭 문서 신규 생성 (없으면)
   - 이벤트 append
   - 종합 문서의 "드롭" 섹션에도 append
4. 보관 이벤트 처리
   - 보관함 신규 생성 (없으면)
   - 보관함에 append (해당 월 그룹)
   - 종합 문서의 "보관 이동" 섹션에도 append
5. 오늘 데일리 노트 생성
   - 할일 섹션 (빈 체크박스 3개)
   - 이월된 할일 섹션 (이월 대상 항목 + 하위 메모 함께)
   - 메모 섹션 (빈)
   - 하단 안내 블록
6. 이번 달 종합 문서의 상단 요약 재계산 후 헤더 블록 덮어쓰기 (완료/드롭/보관 카운트, 평균 소요일)
7. 오늘 날짜가 새 달의 첫 노트면, 오늘 달의 종합 문서도 신규 생성 (빈 골격)

### 3.7 idempotency 및 중복 방지

- 오늘 노트 존재 시 스크립트 전체 스킵 → 이벤트 재처리 없음
- 종합·드롭·보관함은 append-only → 어제 노트 이벤트가 한 번만 append 되는 것을 보장하려면 스크립트가 어제 노트 파일을 처리 완료 후 오늘 노트를 만들어야 함 (오늘 노트 존재 = 어제 이벤트 처리 완료 신호)
- 부작용 순서: 종합/드롭/보관함 append 는 오늘 노트 생성보다 **먼저** 완료. 그래야 오늘 노트가 존재하는 순간 "어제까지의 상태가 반영됐다" 는 게 보장됨.

### 3.8 특수 케이스

**첫날 (어제 노트 없음)**
- 이벤트 없음
- 이월 섹션 비어있는 상태로 오늘 노트 생성

**월 경계 (오늘이 새 달 첫 노트)**
- 어제 노트의 이벤트는 어제가 속한 지난달 종합에 로그
- 오늘 달의 종합 문서를 새로 생성 (빈 골격)
- 오늘 이월 항목은 지난달에서 넘어오는 것도 있음. 카운터·시작일 표기는 그대로 유지 (예: `(3일째 이월, 09-29~)` → 10월 노트에도 그대로)

**긴 부재 후 복귀 (며칠간 스크립트 미실행)**
- launchd 는 놓친 실행을 자동 catch-up 하지 않음
- 최초 로그인 하루만 실행됨. 놓친 날짜들의 데일리 노트는 생성 안 됨
- 결과: 오늘 이월 대상 = "마지막으로 생성된 노트" 의 미완료 항목. 카운터는 그 노트 기준 +1 (놓친 날짜 무시)
- 이건 정확도 손실이지만 복잡도 회피. **향후 catch-up 옵션 추가는 고려 대상** (당장은 아님)

**주말 로그인**
- 토·일에는 노트 생성 안 함 (요일 판단으로 조기 종료)
- launchd 는 실행되지만 스크립트가 스스로 exit

**사용자가 섹션명·이모지를 임의 수정한 경우**
- 스크립트는 정확한 헤더 문자열(`## 📌 할일`, `## ✅ 이월된 할일`, `## 💬 메모`) 을 기준으로 파싱
- 사용자가 헤더를 바꾸면 파싱 실패 → 해당 노트의 이벤트가 감지 안 됨
- 설계 문서와 하단 안내에 "섹션 헤더는 수정하지 말 것" 명시

### 3.9 로그와 진단

- 표준 출력: `~/.claude/scripts/daily-note.log` (기존 유지)
- 에러: `~/.claude/scripts/daily-note-error.log` (기존 유지)
- 매 실행마다 다음 요약을 stdout 에 남김:
  ```
  [2026-09-15] 데일리 노트 생성 완료
    이월: 3건 (카운터 갱신)
    완료: 2건 → 2026-09 종합에 기록
    드롭: 1건 → 2026-09 드롭에 기록
    보관: 0건
  ```
- 에러 시 macOS 알림으로 사용자에게 신호 (osascript notification)

## Part 4. 구현 계획

### 4.1 언어·런타임 선택

기존 스크립트는 **Bash 3.2** (macOS 기본). 신규 요구사항(블록 파싱, 상태 전이, 다중 파일 갱신, 정규식 캡처) 을 bash 로 처리하면 500줄 이상이 되고 유지보수가 힘들다.

권장: **Python 3** (macOS 시스템 `/usr/bin/python3`, 외부 의존성 없음).

- Python 3 는 macOS 12+ 에 기본 포함 (Command Line Tools 설치 시)
- 정규식 캡처·클래스·리스트 조작·파일 IO 관용성이 bash 보다 훨씬 좋음
- launchd 에서 `/usr/bin/python3 /path/to/script.py` 로 직접 호출 가능
- FDA(전체 디스크 접근) 는 `/usr/bin/python3` 에도 추가로 부여 필요

Bash 유지 vs Python 전환은 사용자 결정 지점. 이후 4.2~ 는 Python 기준.

### 4.3 모듈 구조 (Python)

단일 파일 안에 아래 논리적 구성:

```python
# 데이터 모델
@dataclass
class TaskBlock:
    top_line: str              # 최상위 라인 원문
    children: list[str]        # 하위 라인들 (인덴트 포함 원문)
    is_completed: bool         # [x] 여부
    is_dropped_immediate: bool # [-] 여부
    has_archive_marker: bool   # #보관
    has_long_marker: bool      # #장기
    carryover_days: int        # 0 = 활성, 1+ = 이월
    origin_date: date | None   # 이월 시작일

@dataclass
class DailyNoteParsed:
    date: date
    active_blocks: list[TaskBlock]      # 할일 섹션
    carryover_blocks: list[TaskBlock]   # 이월된 할일 섹션
    memo_lines: list[str]               # 메모 섹션

@dataclass
class Events:
    completed: list[TaskBlock]
```

### 4.4 main 함수 흐름 (pseudocode)

```python
def main() -> int:
    today = date.today()

    # 1. 주말 조기 종료
    if is_weekend(today):
        log("weekend, skip")
        return 0

    today_path = daily_note_path(today)

    # 2. idempotent 체크
    if today_path.exists():
        log(f"already exists: {today_path}")
        return 0

    # 3. 어제 노트 찾기
    prev_date = previous_business_day(today)
    prev_path = daily_note_path(prev_date)
    if not prev_path.exists():
        # 최대 14일 역탐색
        prev_date, prev_path = search_last_note(today, max_days=14)

    # 4. 어제 노트 파싱
    if prev_path:
        parsed = parse_daily_note(prev_path, prev_date)
    else:
        parsed = empty_parsed(today)

    # 5. 이벤트 분류 + 카운터 갱신 + 5일 판정
    events = classify_events(parsed, today)

    # 6. 필요 시 월간 문서 생성
    prev_summary = ensure_monthly_summary(prev_date, NOTES_ROOT)

    # 7. 이벤트 append (오늘 노트 생성 전에)
    if events.completed:
        append_completed(events, prev_date, prev_summary)
    if events.dropped:
        drop_path = ensure_monthly_drop(prev_date, NOTES_ROOT)
        append_dropped(events, prev_date, drop_path, prev_summary)
    if events.archived:
        arc_path = ensure_archive(NOTES_ROOT)
        append_archived(events, prev_date, arc_path, prev_summary)

    # 8. 오늘 노트 생성
    write_daily_note(today, events.carrying_over, today_path)

    # 9. 새 달 첫 노트면 오늘 달 종합 골격 생성
    if today.month != prev_date.month:
        ensure_monthly_summary(today, NOTES_ROOT)

    # 10. 상단 요약 재계산 (이번 달)
    recompute_summary_header(today, ensure_monthly_summary(today, NOTES_ROOT))
    if today.month != prev_date.month:
        recompute_summary_header(prev_date, prev_summary)

    log_summary(events)
    notify_success()
    return 0
```

### 4.6 기존 노트 하위호환

과거 노트의 섹션명은:
- `## 📌 오늘의 목표` (새 규격은 `## 📌 할일`)
- `## ✅ 미완료 이월` (새 규격은 `## ✅ 이월된 할일`)

새 파이썬 스크립트는 파싱 시 **두 섹션명 모두 인식** (backward compat). 이유는 과거 노트를 일괄 수정하면 옵시디언 history·수정 시각이 오염되고 이득이 없기 때문.

전이 시점: 신규 스크립트 첫 실행 이후 만들어지는 오늘 노트부터 새 섹션명 적용. 어제 노트가 옛 섹션명이면 그것도 파싱해서 이월 처리.

### 4.7 테스트 시나리오

수동 테스트 체크리스트:

- [ ] 첫 실행 (어제 노트 없음): 빈 이월 섹션으로 오늘 노트 생성
- [ ] 어제 미완료 활성 할일 있음: 이월 섹션에 1일째로 표기
- [ ] 어제 이월 할일 있음(2일째): 오늘 3일째로 표기 + 🟠 + 드롭 예정 문구
- [ ] 어제 이월 할일 있음(4일째): 오늘 5일째 도달 → 드롭 문서로 이동, 이월 안 됨
- [ ] `#장기` 붙은 이월 할일 (4일째): 5일째 되어도 계속 이월
- [ ] `#보관` 붙은 할일: 다음 날 보관함으로 이동, 이월 안 됨
- [ ] `[-]` 표시된 할일: 다음 날 드롭 문서로 이동, 이월 안 됨
- [ ] `[x]` 체크된 활성 할일: 월간 종합에 "당일" 로 로그
- [ ] `[x]` 체크된 이월 할일(3일째): 월간 종합에 "3영업일 소요" 로 로그
- [ ] 블록 하위 메모·서브 체크박스 함께 이월
- [ ] 이월 블록에 오늘 추가한 서브도 다음 날 함께 이월
- [ ] 보관/드롭 시 블록 하위까지 통째로 이동
- [ ] 월요일: 지난 금요일 노트를 어제로 인식 (이월 카운터 정확)
- [ ] 주말(토·일): 스크립트 실행돼도 노트 생성 안 함
- [ ] 월 경계: 어제 이벤트는 지난달 종합에, 오늘 달 종합은 새로 생성
- [ ] 옛 섹션명(`## 📌 오늘의 목표`) 노트도 파싱 성공

각 시나리오는 임시 볼트에서 재현. 실제 볼트에서는 첫 스위치 이후 며칠간 매일 결과 확인.

### 4.8 롤아웃 우선순위

1차 릴리스(당장 구현):
- 데일리 노트 생성 + 이월 + 완료 감지
- 3~4일 보류 시각 표시
- 5일 드롭 규칙
- `#장기` `#보관` `[-]` 마커 처리
- 월간 종합·드롭·보관함 문서 자동 생성/갱신
- 블록 단위 파싱·이동
- 주말 스킵
- 하위호환 파싱

2차 릴리스(필요 시 추가):
- 며칠간 부재 catch-up (놓친 날짜 노트 소급 생성)
- 상단 요약에 소요일 분포 히스토그램
- 옵시디언 Bases 뷰 파일 자동 생성 (완료/드롭 리스트 대시보드)
- 알림 상세화 (이월 5일 초과 임박 알림 등)

3차 릴리스 (나중에):
- 주간 회고 문서 자동 생성 (금요일 저녁)
- 슬랙·기타 채널로 주간 요약 전송
